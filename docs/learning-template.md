# MVP 学习模板

> 每个节点都按同一条路径学习。先写问题和自己的判断，再写实现；不要一开始就抄成熟项目源码。

## 1. 它处在整个流程什么位置？

画流程，只描述输入、输出和上下游。

## 2. 如果没有它，会出现什么问题？

列出真正遇到的问题，不提前讨论解决方案。

## 3. OpenCode 用什么思路解决？

先看架构和流程，不做逐行源码分析。

## 4. 暂时不看源码，我会怎么设计最小方案？

只设计解决当前问题所必需的能力。

## 5. MVP 实现

目标约 100～300 行。复杂度超过范围时，先问是不是把后续节点提前做进来了。

## 6. 验证场景

至少准备：正常路径、边界路径、一个故意制造失败的场景。

## 7. 回到 OpenCode 源码

记录真正相关的源码入口和关键调用链，不追求一次读完整个仓库。

## 8. 我的 MVP vs OpenCode

对比职责、输入输出、状态、异常处理和扩展点。

## 9. 为什么 OpenCode 比我的 MVP 复杂？

把复杂度分成两类：

- 解决同一个核心问题所必需的工程复杂度；
- 成熟产品规模、兼容性、性能和生态带来的复杂度。

# 04 · Schema Drift\n\n状态：`IMPLEMENTED · WAITING FOR RUN`\n\n所属章节：`No UI Harness`\n\n## 核心问题\n\n> Prompt 明明明确规定了输出结构，这个结构本身可靠吗？\n\n这一节不再比较“选了 React 还是 Vue”。\n\n只比较：\n\n```text\n字段有没有丢\n字段有没有多\n字段类型有没有变\nstring[] 会不会变成 object[]\nobject 会不会变成 string\nJSON 能不能正常解析\n```\n\n## 实验条件\n\n同一个 Model、同一个 Prompt，独立运行 5 次。\n\nPrompt 明确规定：\n\n```text\nframework = { name:string, version:string }\n9 个 scalar fields = string\n4 个 list fields = string[]\n顶层必须且只能有 14 个字段\n```\n\n而且明确写了：\n\n```text\n不能增加字段\n不能删除字段\n不能改字段名\n数组项必须全部是 string\n```\n\n但这里只使用自然语言 Prompt。\n\n没有使用：\n\n```text\nJSON Schema API\nfunction calling\nstructured output\nRuntime validator 去拒绝输出\n```\n\n所以仍然属于 No Harness 实验。\n\n## 两个概念\n\n```text\nSchema Violation\n= 某一次输出不符合期望 Schema\n\nSchema Drift\n= 多次 Run 之间，同一个字段的实际 Shape 发生变化\n```\n\n例如：\n\n```text\nRun 1 pages = string[]\nRun 2 pages = object[]\nRun 3 pages = string[]\n\n=> pages 出现 Schema Drift\n```\n\n如果 5 次全部都返回 object[]，而期望是 string[]：\n\n```text\n= Schema Violation\n≠ Schema Drift\n```\n\n因为它虽然一直错，但 Shape 没有在 Run 之间漂。\n\n## 运行\n\n```bash\nnpm run openui:01:04\n```\n\n程序会输出：\n\n```text\n每个 Run 的 schema violations\n每个字段的实际 shape\nPer-Run Schema Result\nShape Drift Comparison\n```\n\n最终两个核心数字：\n\n```text\nschema violation runs : X / 5\nshape drift fields    : Y / 14\n```\n\n## 怎么理解结果\n\n如果出现 Violation / Drift：\n\n> 自然语言 Prompt 表达了期望，但没有把期望变成可靠的执行约束。\n\n如果 5 次全部匹配：\n\n> 只能说明当前 5 个样本都遵守了 Prompt，不能推出 Prompt 等价于 Runtime Schema Enforcement。\n\n## Done\n\n跑完后能回答：\n\n- [ ] Schema Violation 和 Schema Drift 有什么区别？\n- [ ] 为什么这次 Prompt 必须写得很明确？\n- [ ] 哪些字段发生了类型或 Shape 变化？\n- [ ] 为什么 Prompt Constraint 不等于 Runtime Constraint？\n- [ ] 即使 5 次都匹配，为什么仍不能说 Schema 已被系统保证？\n\n下一节：\n\n```text\n05 · No Harness Observation\n```
